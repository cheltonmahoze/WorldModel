# NEXUS OS

**AI Revenue & Operations Intelligence Platform** — a multi-tenant B2B SaaS that answers one
question for a revenue organisation:

> Where is the company losing money, where is the growth opportunity, and what action should be
> taken now?

Everything in the product exists to close that loop: data lands in the workspace, engines turn it
into quantified findings, and every finding carries an owner, a financial impact and the action that
follows it.

---

## What is in the product

| Module | What it does |
| --- | --- |
| **Overview** | Executive command centre: Revenue €2.84M (+18.7%), Pipeline €8.42M (+24.1%), Conversion 18.4% (+3.2 pts), Operational Efficiency 87.6% (+9.8 pts) — all computed from the database, each KPI carrying its comparison, formula and 12-month series. |

| **Opportunities** | Opportunity engine across revenue expansion, cost reduction, retention, sales acceleration, operational efficiency and risk prevention — each with estimated financial impact, confidence, priority, source, owner, due date and lifecycle (Detected → Reviewing → In progress → Completed / Dismissed). |
| **Risks** | Risk register with revenue, customer and operational exposure: severity, probability, financial impact, the related entity, a recommendation and an owner. |
| **Revenue** | MRR/ARR, pipeline, win rate, average deal size, sales cycle, CAC, LTV, churn, expansion revenue and NRR, with period comparison, segmentation and a linear forecast. |
| **Customers** | 360° customer record — company data, contracts, revenue, contacts, opportunities, tickets, activities, product usage and churn risk — plus a Customer Health Score (0–100) built from engagement, revenue, activity, support and usage. |
| **Operations** | Support SLA performance, workload and capacity, stalled deals and the background job queue with manual runs. |
| **Analytics** | Cross-filterable analysis (period, department, region, segment, product, owner) with charts, pivot tables, drill-down, temporal comparison and CSV export. |
| **Automations** | Visual WHEN → IF → THEN builder (trigger → conditions → steps), versioned rules, execution ledger with per-step outcomes, and activate / pause / run-now / delete. |
| **Integrations** | Fifteen-provider catalogue across 7 categories — CRM, communication, finance, productivity, marketing, support and data, with connect, configure, sync-now, health and error state. Unconfigured providers are labelled as such — nothing is faked. |

| **Audit log** | Every write: actor, role, action, entity, before/after diff, IP, user agent, severity, with faceted filtering and export. |
| **Notifications** | Opportunity detected, risk detected, task assigned, automation completed, integration error, report generated — read state, bulk actions and deep links to the entity. |
| **Reports** | Saved reports over eight exportable datasets, with scheduling, formatting, recipients, run history and CSV export. |

Global surfaces: **⌘K command palette** (search customers, opportunities, risks, users and pages;
create records; open analytics; export), notification centre, organisation switcher, theme toggle,
and dedicated empty / loading / error states for every module.

## Architecture

```
src/
  app/                    App Router — (workspace) modules, auth screens, 64 API route files
  components/             UI primitives, application chrome, charts, domain kit
  hooks/                  TanStack Query wrappers, hotkeys, debounce, persistent state
  lib/                    formatting, RBAC matrix, plans, integrations catalogue
  server/
    api.ts                route() — auth → RBAC → Zod → rate limit → envelope
    auth/                 password hashing (scrypt), session issue/rotate/revoke
    engines/              metrics, insight rules, risk scoring, health, efficiency, KPIs
    services/             notifications, webhooks, automations, reports, integrations
    jobs.ts               background job catalogue, queue, retry/backoff, handlers
    validation.ts         every request/response contract in one place
scripts/
  dev-db.ts               embedded PostgreSQL for local development
  db-migrate.ts           applies prisma/migrations (offline, no engine download)
  run-seed.ts             deterministic demo tenant (versioned, idempotent)
  worker.ts               background worker (`--once`, `--interval`, `--batch`)
  e2e.ts                  end-to-end HTTP suite (see Verification)
```

**Multi-tenancy.** Platform → Organisation → Team → User → Data. Every table is scoped by
`organizationId`, every query filters on the active organisation from the session, and the e2e suite
proves isolation by signing a second tenant in and asserting it cannot see the first tenant's rows.

**RBAC.** Owner, Admin, Manager, Analyst, Member with a 50/40/30/20/10 rank model and an explicit
permission matrix (`src/lib/rbac.ts`). Permissions are declared on the route, not in the handler, so
a missing permission fails closed — reads and writes are separated (`customers:read` vs
`customers:write`, `opportunities:write`, `integrations:manage`, `audit:read`, `analytics:export`, …).

**API contract.** Uniform envelope: `{ data, meta }` for collections (`total`, `page`, `pageCount`,
`hasMore`, plus facets and summaries), `{ data }` for objects, and `{ error: { code, message,
requestId } }` for failures. Validation failures are `422 VALIDATION_ERROR`, missing records `404`,
conflicts `409`, plan limits `402`, rate limits `429` — always with a user-facing sentence and never
a stack trace.

**Security.** scrypt password hashing, hashed session tokens with rotation and revocation, CSRF-safe
same-site cookies, per-route rate limiting (auth 30/5min, write 120/min, read 600/min, export
20/5min), server-side validation on every mutation, tenant-scoped queries, audited writes, least
privilege by default, and one-time invitation/reset tokens that are never returned by the API in
production.

**Background jobs.** Nine handlers (`metrics.rollup`, `intelligence.engines`, `risk-engine.rescore`,
`integrations.*.sync`, `reports.scheduled.*`, `webhooks.dispatch.retry`, `billing.usage.rollup`,
`notifications.digest`, `audit.retention.prune`) with atomic claiming, retry with backoff, and a
worker that runs them out of process.

**Business model.** Starter €99/mo, Growth €399/mo, Scale €999/mo and Enterprise (custom), each with
its own seat, record, automation, retention and integration limits enforced server-side; plan
changes, usage events and the product metrics that back them (MRR, ARR, ARPA, CAC, LTV, churn, NRR,
activation, expansion) are modelled in the database.

## Running it

```bash
npm install
npm run setup          # env, embedded Postgres, migration, demo seed
npm run dev            # http://localhost:3000
npm run worker         # optional: background job worker
```

Open-access entry is enabled by default (`OPEN_WORKSPACE="true"`): any visitor reaches the workspace
without signing in, through `/api/auth/demo`, which issues a **real** session for the demo owner and
audits it like any other sign-in. A deliberate sign-out is respected — the visitor lands on the
sign-in screen and stays there. Set `OPEN_WORKSPACE="false"` for classic credential-only access.

Demo occupant: `alex.morgan@nexus-demo.com` / `NexusDemo2026!` (Owner of the seeded tenant). The seed
also creates a second tenant (Beacon) to exercise isolation, plus teams, customers, opportunities,
tickets, automations, reports, notifications and a year of metrics.

## Verification

```bash
npm run verify         # tsc --noEmit + vitest (24 unit tests)
npm run test:e2e       # 138 HTTP checks against a running server
npm run build          # production build (93 routes, 102 kB shared JS)
```

`scripts/e2e.ts` drives the deployed surface over HTTP and asserts the behaviour a buyer would check:
open access, the full auth lifecycle (signup → verification → recovery → invite → acceptance →
reset → replay refusal), every module and deep link, 26 read endpoints, KPI values, CRUD across
customers/contacts/opportunities/activities/automations/reports/teams/webhooks/API keys, the
notification centre, audit trail, exports, background jobs, RBAC refusals, tenant isolation, error
hygiene, plan guardrails and rate limiting. It is environment-aware: against a production build it
verifies that one-time tokens are never returned instead of consuming them rather than trying to
spend them. Verified green in both modes — `138/138` in development and `134/134 + 2 skipped`
against the production build.

## Environment

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | PostgreSQL connection string |
| `SESSION_SECRET` | session token hashing pepper |
| `APP_NAME` | product name used in metadata |
| `OPEN_WORKSPACE` | `true` allows the open-access entry, `false` requires sign-in |
| `DEMO_EMAIL` | account used by the open-access entry |
| `AI_ENGINE` | `deterministic` (default) or `llm` for LLM-rephrased briefs |
| `OPENAI_MODEL` | provider model used when `AI_ENGINE=llm` |
| `OPENAI_API_KEY` | only read when `AI_ENGINE=llm`; without it the deterministic narrative is kept |
| `TRIAL_DAYS` | length of the trial created at signup |
| `SLACK_WEBHOOK_URL` | optional destination for automation Slack steps |

Copy `.env.example` to `.env`; `npm run setup` does it for you and generates a session secret.
